# Вимоги до об'єктно-орієнтованого проекту

## Загальні вимоги

1. **Мова програмування**: Проект повинен бути реалізований на мові програмування **Java** або **Python**.
2. **Тип проекту**: Створення об'єктно-орієнтованого проекту, який відображає певну предметну область (наприклад, система управління підприємством, бібліотека, магазин тощо).
3. **Підхід до проектування**: Всі класи повинні бути створені згідно з принципами об'єктно-орієнтованого програмування:
   - **Наслідування** (inheritance)
   - **Інкапсуляція** (encapsulation)
   - **Поліморфізм** (polymorphism)
   - **Абстракція** (abstraction)
4. **Інтерфейси та абстрактні класи**: У проекті повинні бути використані хоча б один інтерфейс або абстрактний клас для інкапсуляції поведінки.
5. **Реалізація патернів проектування**: Застосування основних патернів проектування, таких як **Фабричний метод**, **Одиничний патерн** (Singleton), **Стратегія** та інші.

## Вимоги до архітектури

1. **Модульність**: Код повинен бути розбитий на логічні модулі або пакети.
2. **Розширюваність**: Архітектура повинна бути розширюваною, тобто система повинна підтримувати додавання нових функціональностей без змін основного коду.
3. **Незалежність від середовища**: Проект не повинен залежати від конкретної платформи або інтерфейсу.

## Вимоги до класів та їх взаємодії

1. **Кількість класів**: У проекті повинно бути мінімум три класи.
2. **Зв'язки між класами**:
   - Клас повинен мати мінімум один атрибут або метод.
   - Застосування чотирьох основних типів зв'язків між класами:
     - **Наслідування**
     - **Реалізація** (імплементація інтерфейсу)
     - **Залежність**
     - **Агрегація або композиція**
3. **Конструктори**: Кожен клас повинен мати конструктора для ініціалізації об'єкта.
4. **Методи**: Всі методи повинні бути добре документовані, мати зрозумілі імена та бути націленими на виконання однієї конкретної задачі.

## Вимоги до тестування

1. **Юніт-тестування**: Повинен бути написаний набір юніт-тестів для перевірки основних функціональних частин системи.
2. **Тестування взаємодії**: Тести повинні перевіряти взаємодію між класами та правильність виконання основних операцій.

## Вимоги до документації

1. **Коментарі в коді**: Код повинен бути достатньо прокоментований, щоб пояснити основні моменти реалізації.
2. **Документація класів**: Кожен клас повинен бути супроводжений коротким описом, що пояснює його функціональність.
3. **Документація функцій**: Кожна функція повинна бути прокоментована з вказівкою її призначення, параметрів та результатів виконання.

## Технічні вимоги

1. **Інтерфейс користувача (опційно)**:
   - Якщо проект передбачає графічний інтерфейс, то його повинно бути легко використовувати, і він повинен бути зручним.
2. **Перформанс**:
   - Система повинна працювати без значних затримок при обробці основних операцій.
3. **Логування та обробка помилок**:
   - У проекті повинно бути налаштоване логування важливих подій, а також обробка винятків для запобігання збоям програми.

## Вимоги до звітної частини

1. **Звіт**: Кожен проект повинен бути супроводжений звітом, в якому буде описано:
   - Обрана предметна область та її обґрунтування.
   - Опис архітектури та класів.
   - Опис використаних патернів проектування.
   - Короткий опис процесу тестування.
2. **Презентація**: Створення презентації для демонстрації основних функцій системи.

## Завершення

Проект вважається завершеним, якщо виконані всі вимоги щодо функціональності, тестування, документації та архітектури. Усі вимоги повинні бути виконані, а система повинна бути готова до подальшого розширення.
